# CONTEXT - `backend/features/shelf_manager/`

> Reecrit court le 2026-09-16 (V7-05). Ancienne fiche detaillee de mai 2026 retiree (lisible au tag `archive/pre-cleanup`).

`shelf_core.py` : installation shelves Maya/Houdini, Unreal (projet FluxRender + plugin FluxBridge, comme ZBrush = UI + bridge), HDA FLUX construits en live depuis le code (`_build_hdas_live`, table `_HDA_BUILDS`, definition neuve rendue preferee). Aucun `.hda` livre (2026-09-25) : la copie de secours est le dernier build (`%APPDATA%/FLUX/dcc/houdini`).

Boutons pipeline toujours presents sur la shelf Flux Maya (`shelf_FluxPipeline.mel`) : MAJ, CAM (Camera Rig), LIGHT (Light Rig) (ADR 0023).

Shelf Houdini (2026-09-24) : `install_shelf("Houdini")` copie `Flux.shelf` puis appelle `install_hdas` (build live si Houdini connecte, sinon copie stagee), non bloquant, message combine. `remove_shelf` garde les HDA (l'Autostart s'en sert, son uninstall les retire). Tests : `tests/shelf_manager`.

`resources/shelves/houdini/Flux.shelf` (2026-09-24) : un bouton par node FLUX (Import, Export, Anim, Shot, Crowd, Work, Lighting, Render, Sequence, Unreal Live ; 2026-10-10), icone = IconSVG du HDA. Le bouton cree le node dans le reseau courant s'il est du bon contexte, sinon dans `/stage` (LOP) ou un `geo` de `/obj` (SOP). L'ancien outil "Import KineFX" est retire.

HDA a l'ouverture de Houdini (2026-10-13, the maintainer : shelf visible, HDA absents) : avec Houdini ferme, `install_hdas` ne fait que copier le staging (`%APPDATA%/FLUX/dcc/houdini`, rempli seulement par un build live : vide sur un poste neuf, 2 vieux HDA ailleurs). Il ne renvoie plus d'echec et annonce les HDA construits plus tard. `GET /houdini/ping` (routers/dcc.py, `_on_houdini_ping`) lance une fois par connexion, en tache de fond, `ensure_hdas_in_session` : Houdini dit quels types `flux_*` de `_HDA_BUILDS` lui manquent et quel `homeHoudiniDirectory()` il lit ; s'il en manque, build live dans ce `otls` (rien sinon). Pas de second build si un ping est manque pendant le build, pas de boucle apres un echec. `is_hda_installed` compare a `_HDA_BUILDS` (plus au staging).

`purge_hda_backups` (2026-09-24) : supprime les `backup/flux_*_bak*.hda` que Houdini ecrit a chaque reecriture d'un HDA FLUX (otls + staging), apres un build live et au debut de `install_hdas`. Les backups d'autres HDA ne sont pas touches.

Anciens fichiers FLUX (2026-10-10, the maintainer) : `stale_cleanup.py`. Apres "Installer" (et les outils Maya), le Shelf Manager appelle `GET /shelf/stale` et montre une liste a cocher (`app/src/pages/shelf_manager/StaleFilesDialog.tsx`, tout coche par defaut, raison par ligne) ; `POST /shelf/stale/remove` ne supprime qu'un chemin qu'un nouveau scan liste encore. Seuls les fichiers de FLUX sont listes : Houdini `flux_*.hda` contenant des types `flux_*` (HDA studio jamais), Maya `shelf_Flux*.mel` autre que `shelf_Flux.mel`. Raisons Houdini : HDA qui n'existe plus, copie hors du dossier lu par le Houdini ouvert (doublon), `backup/`, copie hors ligne d'un ancien nom. Houdini ouvert dans la meme version : `install_hdas` construit seulement dans son `homeHoudiniDirectory()/otls` (plus de miroir), les autres copies deviennent des doublons proposes. Houdini ferme : miroir dans tous les dossiers comme avant, pas de doublon signale. Les HDA supprimes sont aussi desinstalles du Houdini ouvert. Tests : `tests/shelf_manager/test_stale_cleanup.py`.
