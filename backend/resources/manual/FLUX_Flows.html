PARTIE 1
Flows : vue globale

Etat au 2026-10-23 (phases P0 a P4 codees). Ce qui manque encore est dans Dispo et a venir.

1. Un flow, c'est quoi

Un flow est une petite automatisation du pipeline dessinee en nodes, comme un reseau Houdini ou un Blueprint Unreal : "chaque soir, copie les playblasts du jour dans le dossier des dailies", "quand je clique ce bouton, archive les anciennes versions", "apres un publish de modeling, regenere le proxy". Chaque node fait une seule chose (lire une valeur, tester une condition, copier un fichier, publier) ; les liens disent dans quel ordre et avec quelles donnees.

Un flow est un fichier texte <nom>.flow.yml : lisible, comparable d'une version a l'autre, versionne. L'editeur n'est qu'une facon de le dessiner ; rien n'est cache dans l'app.

2. Objectifs

  • Automatiser sans coder : les TD du projet montent eux-memes leurs outils avec des briques sures, au lieu de demander un script Python.
  • Difficile de se tromper : les ports sont types (un lien impossible est refuse pendant le glisser, avec la raison), chaque probleme est liste avec sa correction en un clic, les nodes qui effacent ou ecrasent sont marques et demandent une confirmation, un essai a blanc montre ce qui se passerait sans rien ecrire.
  • Rien n'est perdu : chaque enregistrement important fige une version, revenir en arriere cree une nouvelle version, supprimer met a la corbeille, l'effacement d'un fichier du projet passe par defaut par ARCHIVE/.
  • Remplacer les actions YAML v1 : le publish de chaque logiciel deviendra un flow (phase P8). En attendant, les actions v1 sont visibles comme flows legacy_* (lecture seule) et le publish tourne toujours sur v1.
  • Zero licence : tout ce que FLUX sait faire seul (textures .tx, proxy USD, controle USD, copie, zip) se fait sans ouvrir de logiciel.

4. Comment un flow s'execute

  1. Depart : un evenement part (clic sur Run dans l'editeur, bouton de page, appel par un autre flow).
  2. Chaine exec : le moteur suit le lien then de l'evenement, execute le node relie, puis suit son then, et ainsi de suite. Un node de branchement (If, Switch, Sequence) choisit la sortie exec a suivre.
  3. Donnees tirees a la demande : quand un node s'execute, ses entrees reliees vont chercher leur valeur. Un node sans port exec (Value, Path, Compare, Math...) est calcule a ce moment-la, une seule fois par tour. Un node de la chaine exec donne ses dernieres sorties ; lire une sortie d'un node pas encore execute est une erreur ("donnee lue avant d'etre produite").
  4. Boucles en blocs comme Houdini : ForEachBegin ... ForEachEnd, ForBegin ... ForEnd, WhileBegin ... WhileEnd. Ce qui est relie entre les deux tourne a chaque tour ; BreakLoop sort de la boucle. Un While a toujours un plafond de tours : jamais de boucle infinie.
  5. Erreurs : un node qui echoue s'entoure de rouge avec le message et le run s'arrete. Pour gerer l'erreur soi-meme (comme un try / except), relier sa sortie on_error : le node passe en "erreur geree" et la suite part de la.
  6. Bypass : un node bypasse est saute, le flux continue par son then.
  7. Fin : le run se termine quand la chaine exec n'a plus de suite. Chaque node garde son etat (fini, erreur, saute).

Limites : 4 runs a la fois sur le poste ; un node a 120 s par defaut (timeout_s). Le reglage du flow "Si deja en cours" (run_policy) dit quoi faire quand un run est demande alors qu'un autre tourne : skip_if_running (ignore) ou queue (file d'attente, 20 max).

Textes : tokens, variables, motifs

Dans les parametres texte et chemin (pas dans une valeur arrivee par un lien) :

  • {token} : un token du projet ou du run ({project}, {user}, {shot}, {date:%Y%m%d}...). Un token inconnu est une erreur avec une suggestion ({shto} -> {shot}).
  • ${variable} : une variable du flow (panneau Params du flow > Variables).
  • $FLUX/... en tete d'un chemin : la racine FLUX, pour un chemin portable entre postes.
  • Motifs facon Houdini (ListFilter, ListFiles, FindPublishes...) : * n'importe quoi, ** sous-dossiers, ? un caractere, [abc] un caractere parmi, ^ ou ! exclut. Plusieurs motifs separes par des espaces, lus de gauche a droite : *.abc ^*_tmp* garde les .abc sauf les temporaires. Motif vide = ne garde rien.

Interface et variables d'un flow

Sans node selectionne, le panneau Params montre le flow lui-meme :

  • Proprietes : libelle, description, "Si deja en cours".
  • Entrees (interface) : les parametres exposes du flow (id, type, libelle, defaut, choix). Le Run de l'editeur les demande dans un formulaire ; une page TOOL les affichera (P7) ; un FlowCall les recoit en entrees. Un node FlowInput lit leur valeur dans le graph.
  • Sorties (sous-flow) : les valeurs qu'un flow rend a celui qui l'appelle, ecrites par FlowOutput.
  • Variables : valeurs locales a un run, lues par GetVariable ou ${nom}, ecrites par SetVariable.

5. Ouvrir l'editeur

Parametres > Avance > carte "Actions (YAML)" > Ouvrir le graph. La fenetre s'ouvre a part.

  • Il faut la case TD (Parametres > User > Flows) pour editer et lancer ; la case Team TD pour ecrire un flow d'equipe ou de projet, un node Python, ou migrer les actions v1. Ces cases sont un garde-fou, pas une securite.
  • L'ancien editeur d'actions v1 reste joignable depuis Parametres avances (lecture et edition des actions v1) jusqu'a P8.

Disposition : barre du haut (fichier, version, problemes, Run, Essai, Runs, Layout, groupe, note, recherche) ; Shelf (un onglet par famille, les nodes courants) ; le graph au centre ; le panneau Params a droite ; le dock en bas (Problemes, Runs) ; le tiroir Catalogue (tous les nodes, recherche).

6. Creer un flow

  1. Fichier > Nouveau (Ctrl+N) : un nom en minuscules (daily_render, lettres, chiffres, _) et une portee :
    • Perso : pour soi (USER/<NOM>/flows/), case TD ;
    • Pipe (equipe) : pour toute l'ecole (CONFIG/extensions/flows/), case Team TD ;
    • Projet : pour le projet actif seulement (<projet>/_flux_setup/flows/), case Team TD.
  2. Poser un evenement : onglet Evenements du Shelf > Manual (lance par Run) ou Button (lance par un bouton de page).
  3. Ajouter des nodes : clic sur un node du Shelf (pose au centre), glisser depuis le Shelf ou le Catalogue (pose au point de depot), ou Tab dans le graph (recherche par nom, type, alias ou doc ; Entree pour poser a la souris).
  4. Relier : glisser d'une sortie vers une entree. Pendant le glisser, les ports compatibles sont entoures, les autres pales ; survoler un port refuse donne la raison ("Une liste de chemins ne va pas dans un chemin : mets un ForEach"). Lacher un lien dans le vide ouvre le menu Tab limite aux nodes compatibles, deja relies.
  5. Regler : cliquer un node, remplir ses parametres dans Params. Une entree reliee affiche <- n4.items en gris.
  6. Exposer ce que l'artiste doit choisir : Params du flow > Entrees (interface), puis un FlowInput dans le graph.
  7. Verifier : le dock Problemes se met a jour tout seul. Cliquer une ligne zoome sur le node ; "Corriger" applique la correction proposee.
  8. Tester : Run (brouillon), puis Enregistrer et Essai a blanc (voir §8).

Un flow livre (legacy_*, example_*) est en lecture seule : Fichier > Enregistrer sous en fait une copie modifiable dans une autre portee.

Exemple complet livre : example_daily_render (Button > FindPublishes > MakeDir > ForEach(PublishFields > Copy) > Notify).

8. Enregistrer, versions, lancer

  • Enregistrer (Ctrl+S) : ecrase le fichier de travail. Permis meme avec des erreurs (le flow est alors marque "invalide", non activable).
  • Enregistrer et incrementer (Alt+Maj+S) : fige une nouvelle version vNNN (seulement si le contenu a change).
  • Enregistrer sous (Ctrl+Maj+S) : copie sous un autre nom ou une autre portee.
  • Versions (clic sur v003 dans la barre) : liste des versions (date, artiste), Voir (lecture seule), Revenir a cette version (cree une nouvelle version identique : rien n'est perdu), onglet Historique (qui a fait quoi).
  • Nodes destructifs : enregistrer un flow ou un node ! a ete ajoute ou passe en mode destructif ouvre un dialogue qui les liste ; il faut glisser pour valider.
  • Quitter = enregistrer : fermer la fenetre ou changer de flow enregistre (avec le meme dialogue si besoin). Un brouillon est aussi garde localement en cas de fermeture brutale et propose a la reouverture.
  • Conflit : si quelqu'un a enregistre pendant que tu editais, FLUX le dit (qui, quand) : voir sa version, enregistrer par-dessus (la sienne reste dans l'historique) ou annuler.
  • Run : lance le document ouvert tel quel (brouillon, aucune version creee), avec le formulaire de l'interface. Les nodes s'allument en direct (en cours, fini, erreur, saute). Stop annule.
  • Essai (essai a blanc) : lance le fichier enregistre ; les nodes a effet ne font rien et ecrivent ce qu'ils auraient fait dans le rapport. A faire avant toute activation.
  • Runs (dock) : historique des runs du flow ; clic = logs et graph colore par l'etat de chaque node.

9. Activer

Un flow actif tourne tout seul quand son evenement arrive (bouton de page, horaire, nouveau fichier, publish...). C'est la version activee qui tourne, pas le fichier de travail : on peut continuer a editer un flow actif sans risque.

Bouton Activer (barre du haut) : un dialogue a 3 voyants sur la derniere version figee (Enregistrer et incrementer) :

  1. 0 erreur ;
  2. avertissements lus : une case par avertissement ;
  3. essai a blanc reussi sur cette version : bouton dans le dialogue, rapport de ce qui se serait passe.

Un flow avec un node ! s'active en glissant pour confirmer. Une nouvelle version ne change pas la version active (tag "vN non activee") : il faut reactiver. Droits : perso = TD, equipe et projet = Team TD. Un legacy_* ne s'active pas.

Qui execute : les evenements locaux (Run, bouton, OnPublish, SceneOpened) tournent sur le poste ou ils arrivent. Les evenements globaux (Schedule, NewFile, When) d'un flow d'equipe ou de projet tournent sur un seul poste : le premier FLUX ouvert prend un verrou (CONFIG/extensions/runs/host.lock) ; s'il se ferme, un autre reprend en une minute environ. Un flow perso tourne seulement sur le poste de son auteur. Sans FLUX ouvert, rien ne tourne. Reglages avances : "Flows actifs sur ce poste" (FLUX_FLOWS_SCHEDULER) et "Flows apres publish" (FLUX_FLOWS_HOOKS).

11. Pages TOOL

Une page TOOL est l'ecran d'un ou plusieurs flows, construit sans code : onglet TOOL du groupe ASSETS (il apparait des qu'une page existe, ou pour un Team TD). Tout le monde voit et utilise les pages ; un Team TD les cree et les edite.

  • Creer : TOOL > Nouvelle : libelle, portee (equipe = tous les projets, ou le projet ouvert), depart vide, depuis un modele (Daily render, Team, Board) ou copie d'une page.
  • Editer (bouton Editer, 4 colonnes facon Edit Parameter Interface) : Palette (cliquer un widget l'ajoute sous la selection), Arbre (dossiers > lignes > widgets, 4 par ligne au plus, fleches pour deplacer), Proprietes, Apercu (les boutons n'y lancent rien). Ctrl+S enregistre, Fermer enregistre puis quitte, Ctrl+Z / Ctrl+Y annulent.
  • Bouton : "Au clic" choisit un flow et lui ajoute un node Button du meme id (une nouvelle version du flow, a activer) ; le bouton lance la version active du flow, grise avec la raison si le flow n'est pas actif. Sous le bouton : en cours (Stop), fini il y a 3 min par ..., ou l'erreur.
  • Champ : "Lie a" choisit un parametre de l'interface du flow (seuls les types compatibles sont proposes) ; la valeur part avec le clic. "Se souvenir" garde la derniere saisie de chaque artiste.
  • Ids : proposes depuis le libelle ; renommer un bouton lie met a jour la page et le flow en une fois ; renommer un parametre dans l'editeur de flows propose de mettre a jour les pages.
  • Donnees partagees : les widgets Fil, Tableau, Cartes, Calendrier et Board lisent une collection de la page (creee avec le widget). Chaque artiste ecrit dans son propre fichier (pages_data/<page>/<collection>/<NOM>.jsonl, dans le projet ou l'equipe), FLUX les fusionne a la lecture : pas de conflit sur un partage ou OneDrive. Les autres postes apparaissent en quelques secondes.
  • Flows lies aux donnees : PageData part a chaque nouvel enregistrement (ex. un message > Notify), PageDataRead / PageDataWrite lisent et ecrivent (ex. rappels du calendrier chaque matin).

Evenements

Le point de depart d'un flow. Pas d'entree exec ; un flow peut en avoir plusieurs.

Buttonevent.button

Part quand on clique un bouton d'une page TOOL (P7), ou quand on clique Run dans l'editeur. Les valeurs saisies dans le formulaire du flow sortent par values.

  • Sorties : then, values (dict des entrees de l'interface).
  • Reglage : button_id, l'identifiant du bouton de page qui lance ce flow.

Exemple : bouton "Daily" d'une page de prod : Button (button_id: daily_render) > FindPublishes > Copy.

Manualevent.manual

Depart a la main : Run dans l'editeur, ou appel par un autre flow avec FlowCall (c'est par lui que demarre un sous-flow). A utiliser pour tout flow d'outillage ou de test.

  • Sorties : then, values (les entrees de l'interface).

Exemple : un sous-flow archive_old_versions commence par Manual ; un autre flow l'appelle avec FlowCall.

Scheduleevent.schedule

Part a heure fixe (heure du poste qui execute), tous les jours ou certains jours. Flow d'equipe ou de projet : un seul poste FLUX l'execute (celui qui tient le verrou) ; flow perso : ton poste. Si FLUX etait ferme a l'heure, le creneau est rattrape une fois au prochain lancement (missed: catch_up_once) ou oublie (skip). Le run prend les valeurs par defaut de l'interface du flow.

  • Sorties : then, fired_at (creneau, ISO), missed (vrai pour un rattrapage).
  • Reglages : days (daily ou mon,tue,wed,thu,fri,sat,sun), time (HH:MM), missed.

Exemple : Schedule (days: mon,tue,wed,thu,fri, time: 08:00) > FindPublishes > Copy vers le dossier des dailies.

NewFileevent.new_file

Part pour chaque nouveau fichier qui arrive dans un dossier. Le premier scan sert de base : les fichiers deja la ne declenchent rien. Les fichiers vus sont gardes, ceux arrives pendant que FLUX etait ferme partent au lancement suivant. Par defaut un fichier part quand sa taille est la meme sur deux scans (copie finie).

  • Entree : folder (dossier surveille).
  • Sorties : then, path, name, dir.
  • Reglages : pattern (motif, defaut *), recursive, every_s (min 5, defaut 30 ; sous 10 s : avertissement de charge reseau), wait_stable.

Exemple : NewFile (folder: $FLUX/DROP/refs, pattern: *.jpg *.png) > ConvertImage vers $FLUX/REFS.

Whenevent.when

Part quand une condition passe de faux a vrai. La condition est calculee par des nodes purs (Exists, Compare, And...) toutes les every_s secondes ; la premiere evaluation sert de base ; une erreur est notee sans declencher.

  • Entree : condition (booleen).
  • Sortie : then.
  • Reglages : every_s (min 5, defaut 30).

Exemple : Exists ($FLUX/PROJ/render/shot010/done.txt) > When > Notify "shot010 rendu".

OnPublishevent.on_publish

Part apres chaque publish reussi sur ce poste, quel que soit le logiciel (le flow tourne chez l'artiste qui publie). Soft, type et version sont deduits du nom et de l'extension du fichier. Le reglage avance "Flows apres publish" (FLUX_FLOWS_HOOKS) coupe cet evenement.

  • Sorties : then, publish (le publish, lisible avec PublishFields), project.
  • Reglages : soft, type, name (motifs, vide = tous).

Exemple : OnPublish (soft: houdini, type: usd) > RefreshShotStage pour remettre a jour le stage du plan.

SceneOpenedevent.scene_opened

Part quand une autre scene est ouverte dans Maya, Houdini ou Nuke sur ce poste. FLUX interroge chaque instance ouverte toutes les every_s secondes (rien a installer dans le logiciel) ; les scenes deja ouvertes au lancement ne declenchent rien. Un script du logiciel peut aussi l'envoyer : POST /flows/events/scene_opened.

  • Sorties : then, scene, soft, session (instance : port et pid ; servira aux nodes DCC).
  • Reglages : soft (maya, houdini, nuke), every_s (min 2, defaut 5).

Exemple : SceneOpened (soft: maya) > Notify "pense a mettre a jour tes references".

PublishRequestevent.publish_request

Depart des flows de publish par logiciel (publish_maya, publish_houdini) : le Publisher du logiciel envoie son formulaire, ses valeurs remplissent l'interface du flow. D'ici la bascule du Publisher (P8), on lance ces flows avec Run.

  • Sorties : then, values (le formulaire), soft.
  • Reglage : soft.

Exemple : PublishRequest (soft: maya) > MayaInstance (live_connect_only) > mayPublish (name: ${name}).

PageDataevent.page_data

Part pour chaque enregistrement ajoute (ou modifie) dans une collection d'une page TOOL (un message du fil, une carte du board, une date du calendrier), quel que soit le poste qui l'a ecrit : les journaux de tous les auteurs sont relus quand ils bougent. La premiere lecture sert de base. Un flow d'equipe sur une collection rangee par projet surveille chaque projet. Les runs partent l'un apres l'autre (aucun message perdu), 20 au plus par lecture.

  • Sorties : then, record (l'enregistrement : ses champs, _by, _at), user (qui l'a ecrit), project.
  • Reglages : page, collection, on (added, changed ou any, defaut added), every_s (min 5, defaut 10).

Exemple : PageData (page: team, collection: messages) > Notify "nouveau message de {user}".

Data

Des valeurs : constantes, parametres du flow, variables, lectures de fichiers. Pas de port exec (sauf SetVariable) : calcules quand un node les lit.

Valuedata.value

Une valeur fixe tapee dans le node : texte, nombre, booleen, liste, dictionnaire ou motif. Le type choisi fixe le type de la sortie, donc ce qu'on peut y brancher.

  • Sortie : value.
  • Reglages : type (str, int, float, bool, list, dict, pattern), value.

Exemple : Value (type: int, value: 3) vers max_items d'un ForEach pour ne traiter que 3 elements pendant un test.

GetVariabledata.get_variable

Lit une variable du flow (declaree dans Params du flow > Variables). Une variable vit le temps d'un run ; elle vaut sa valeur initiale tant qu'aucun SetVariable ne l'a ecrite.

  • Sortie : value.
  • Reglage : name, la variable.

Exemple : compter les fichiers copies : GetVariable (copied) > Math add 1 > SetVariable (copied) dans la boucle.

SetVariabledata.set_variable

Ecrit une variable du flow, convertie dans le type declare. C'est un node exec : l'ecriture se fait a son tour dans la chaine, ce qui garantit l'ordre.

  • Entrees : exec, value. Sorties : then, on_error, value (la valeur ecrite).
  • Reglage : name.

Exemple : garder le dernier publish trouve dans une boucle pour le notifier apres la fin.

FlowInputdata.flow_input

Donne la valeur d'un parametre expose du flow (Params du flow > Entrees) : ce que l'artiste a saisi dans le formulaire du Run ou de la page, sinon le defaut. C'est aussi par la qu'un sous-flow recoit les entrees de son FlowCall.

  • Sortie : value.
  • Reglage : id, le parametre de l'interface.

Exemple : interface dest_folder (dir, defaut $FLUX/DAILY) > FlowInput (dest_folder) > PathJoin base.

Pathdata.path

Un chemin fixe. Accepte $FLUX/... (portable entre postes), {token} et ${variable}. Un chemin relatif part du dossier du projet (ou reste tel quel avec relative_to: absolute). C'est une constante : value et relative_to se saisissent, ils ne recoivent pas de lien.

  • Sorties : path (le chemin), dir (le meme, type dossier).
  • Reglages : value, relative_to (project ou absolute).

Exemple : Path (value: {project_path}/ARCHIVE) comme dossier a lister par ListFiles.

TokenPathdata.token_path

Compose un chemin du projet avec les tokens, comme le Publisher : choisis la classe, le nom, le type (asset) ou la sequence, le plan et la task (shot), le node donne le dossier du publish. level: last donne le fichier LAST de ce dossier (le layout est plat : <base>_LAST.<ext>, choisis le format avec ext), level: entity le dossier de l'asset ou du plan. Les menus proposent les tokens du projet ; chaque reglage peut aussi etre relie. Lecture : tourne aussi en essai a blanc. Le flow doit tourner dans un projet.

  • Sorties : path, dir (le meme si c'est un dossier existant, sinon vide), exists.
  • Reglages : mode (asset, shot), class, name, type (asset), task, seq, shot (shot), instance (null par defaut), level (publish, last, entity), ext (format du LAST).

Exemple : TokenPath (asset, CHAR, HERO, MOD) > path vers ListFiles.folder pour lister les publishs du modeling.

PythonValuedata.python_value

Lit une variable d'un fichier .py sans l'executer (lecture du texte : nombres, textes, listes, dicts seulement). Sert a reutiliser une liste ou un reglage deja ecrit dans un script.

  • Sortie : value.
  • Reglages : file (le .py), name (la variable du module).

Exemple : lire DEPARTMENTS = ["mod", "rig", "surf"] d'un script d'outil pour boucler dessus avec ForEach.

JsonValuedata.json_value

Lit une valeur dans un JSON par son chemin pointe a.b[0].c, depuis un fichier ou depuis un dict relie. found dit si la cle existe ; sinon la sortie vaut default.

  • Entree : json (dict, prioritaire sur le fichier). Sorties : value, found.
  • Reglages : file, key, default.

Exemple : JsonValue (file: {project_path}/production.json, key: settings.fps, default: 24) > Template.

Templatedata.template

Compose un texte a partir d'un modele : tokens du run ({project}, {user}, {date:%Y%m%d}), variables ${nom}, $FLUX, et les cles du dict relie a values ({name}, {version}).

  • Entree : values (dict). Sortie : text.
  • Reglage : text, le modele.

Exemple : Template ("{shot}_daily_{date:%Y%m%d}.mov") pour nommer un fichier de livraison.

Contextdata.context

Les valeurs du run en cours : projet et son dossier, asset, sequence, plan, artiste, date, heure, nom du flow. Vides si le depart ne les donne pas.

  • Sorties : project, project_path, asset, seq, shot, user, date, time, flow.

Exemple : Context.user vers Ping.user pour prevenir l'artiste qui a lance le flow.

Logique

Tester et choisir. If et Switch choisissent la branche exec ; les autres calculent un booleen ou une valeur.

Iflogic.if

Une seule branche s'execute : then si la condition est vraie, else sinon. Les deux branches peuvent se rejoindre plus loin sur la meme entree exec.

  • Entrees : exec, condition (bool). Sorties : then, else, on_error.

Exemple : Exists (dossier de sortie) > If : else > MakeDir, puis les deux branches vers Copy.

Switchlogic.switch

Prend la sortie du cas egal a la valeur (egalite exacte, pas de motif), sinon default. Jusqu'a 8 cas, une sortie case_N par valeur de la liste cases.

  • Entrees : exec, value. Sorties : case_0 a case_7, default, on_error.
  • Reglages : cases (liste), type (str, int, float).

Exemple : Switch (cases: [mod, rig, surf]) sur le departement : chaque branche publie a sa facon.

Comparelogic.compare

Compare a et b : egal, different, plus petit, plus grand, contient, commence par, finit par, ou matches (a contre le motif b, par exemple *.abc ^*_tmp*).

  • Entrees : a, b. Sortie : result (bool).
  • Reglage : op (eq, ne, lt, le, gt, ge, contains, startswith, endswith, matches).

Exemple : Compare (op: gt) entre ListLength et Value 0 > If : ne notifier que s'il y a des fichiers.

Andlogic.and

Vrai si toutes les entrees reliees sont vraies (2 a 4 entrees).

  • Entrees : a, b, c, d (c et d optionnelles). Sortie : result.

Exemple : And (Exists source, Not Exists dest) > If pour copier seulement ce qui manque.

Orlogic.or

Vrai si au moins une entree reliee est vraie (2 a 4 entrees).

  • Entrees : a, b, c, d. Sortie : result.

Exemple : Or (Compare ext == .ma, Compare ext == .mb) pour reconnaitre une scene Maya.

Notlogic.not

Le contraire du booleen.

  • Entree : value. Sortie : result.

Exemple : Exists > Not > If pour creer un dossier seulement s'il manque.

IsEmptylogic.is_empty

Vrai si la valeur est vide : texte vide, liste ou dict vide, rien.

  • Entree : value. Sortie : result.

Exemple : FindPublishes.items > IsEmpty > If : then > Notify ("Rien publie aujourd'hui").

Existslogic.exists

Le fichier ou le dossier existe-t-il ? is_dir dit si c'est un dossier.

  • Entree : path. Sorties : result, is_dir.

Exemple : verifier qu'un .tx existe deja avant de lancer ConformTexture.

Selectlogic.select

Choisit une valeur, pas une branche : a si la condition est vraie, sinon b. Equivalent de a if condition else b.

  • Entrees : condition, a, b. Sortie : value.

Exemple : dossier de sortie = Select (case "en local", dossier perso, dossier du projet).

Operateurs

Boucles, ordre, calculs sur nombres, textes, listes, chemins et dates.

ForEachBeginoperator.foreach_begin

Ouvre une boucle : le corps (les nodes relies entre Begin et End) tourne une fois par element de la liste. item est l'element du tour, index son rang. Liste vide : le corps est saute, la suite part du done de ForEachEnd.

  • Entrees : exec, list. Sorties : loop (vers le corps), item, index, count, on_error.
  • Reglages : max_items (plafond, 10000), mode (reserve).

Exemple : FindPublishes.items > ForEachBegin > PublishFields + Copy > ForEachEnd.

ForEachEndoperator.foreach_end

Ferme la boucle de son ForEachBegin (apparie par l'editeur). A chaque tour, garde la valeur reliee a collect ; a la fin, results est la liste de ces valeurs et le flux repart de done.

  • Entrees : exec, collect. Sorties : done, results, on_error.
  • Reglage : begin (pose par l'editeur).

Exemple : collect <- Copy.path : results = liste des fichiers copies, envoyee a StrJoin puis Notify.

Sequenceoperator.sequence

Execute ses sorties dans l'ordre, l'une apres l'autre. Une sortie exec n'acceptant qu'un lien, c'est le node pour enchainer plusieurs suites independantes depuis un meme point.

  • Entree : exec. Sorties : then_0 a then_7, on_error.
  • Reglage : count (1 a 8).

Exemple : apres un publish, Sequence : then_0 > GenerateProxy, then_1 > UsdCheck, then_2 > Notify.

ForBeginoperator.for_begin

Boucle sur des nombres : le corps tourne pour chaque index de start a end inclus, avec un pas (negatif pour descendre). Plafonnee par max_iterations.

  • Entrees : exec, start, end, step. Sorties : loop, index, on_error.
  • Reglages : max_iterations (1000), mode (reserve).

Exemple : ForBegin (1 a 10) > StrFormat 03d > Template "SH{index}" pour preparer 10 noms de plans.

ForEndoperator.for_end

Ferme la boucle de son ForBegin ; la suite part de done apres le dernier tour.

  • Entree : exec. Sorties : done, on_error.
  • Reglage : begin (pose par l'editeur).

Exemple : fin du corps d'une boucle de 1 a 10, puis done > Notify ("10 dossiers crees").

WhileBeginoperator.while_begin

Le corps tourne tant que la condition est vraie ; elle est relue apres chaque tour. Atteindre max_iterations est une erreur : jamais de boucle infinie.

  • Entrees : exec, condition. Sorties : loop, index, on_error.
  • Reglage : max_iterations (1000).

Exemple : attendre qu'un rendu ecrive son fichier : WhileBegin (Not Exists) > Wait 10 s > WhileEnd.

WhileEndoperator.while_end

Ferme la boucle de son WhileBegin ; la suite part de done quand la condition devient fausse.

  • Entree : exec. Sorties : done, on_error.
  • Reglage : begin (pose par l'editeur).

Exemple : done > Notify ("Le rendu est arrive").

BreakLoopoperator.break_loop

Sort tout de suite de la boucle qui l'entoure : la suite part du done du End de cette boucle.

  • Entree : exec.

Exemple : dans un ForEach, If (fichier trouve) > BreakLoop pour s'arreter au premier resultat.

Mathoperator.math

Calcule a op b (add, sub, mul, div, mod, min, max) ou op a (round, floor, ceil, abs). as_int donne le resultat en entier.

  • Entrees : a, b. Sorties : result (float), as_int.
  • Reglage : op.

Exemple : Math (sub) entre deux index pour un nombre d'images, ou Math add 1 pour un compteur.

Nulloperator.null

Laisse passer la valeur telle quelle. Sert a ranger le graph : un point de rassemblement d'ou partent plusieurs liens.

  • Entree : value. Sortie : value.

Exemple : Null nomme OUT_FOLDER relie a tous les nodes qui ecrivent dans le meme dossier.

StrJoinoperator.str_join

Joint une liste de textes avec un separateur.

  • Entree : items. Sortie : text.
  • Reglage : sep.

Exemple : ForEachEnd.results > StrJoin (sep: ", ") > Notify : "chair, table, lamp copies".

StrSplitoperator.str_split

Coupe un texte a chaque separateur (vide = aux espaces).

  • Entree : text. Sortie : items.
  • Reglage : sep.

Exemple : StrSplit (sep: _) sur chair_mod_v003 puis ListGet 0 pour retrouver le nom de l'asset.

StrReplaceoperator.str_replace

Remplace find par with dans le texte ; regex pour une expression reguliere.

  • Entree : text. Sortie : text.
  • Reglages : find, with, regex.

Exemple : StrReplace (find: _WIP, with: "") pour nettoyer un nom avant de publier.

StrCaseoperator.str_case

Majuscules, minuscules, Titre, ou espaces retires au debut et a la fin.

  • Entree : text. Sortie : text.
  • Reglage : op (upper, lower, title, strip).

Exemple : StrCase (upper) sur le nom d'artiste pour le dossier ARCHIVE/<date>_<ARTISTE>.

StrFormatoperator.str_format

Met une valeur en forme avec un format Python : 03d donne 007, .2f donne 3.14.

  • Entree : value. Sortie : text.
  • Reglage : spec.

Exemple : index d'un ForBegin > StrFormat 03d > Template "v{version}" pour v001, v002...

ListLengthoperator.list_length

Nombre d'elements d'une liste.

  • Entree : list. Sortie : length.

Exemple : ListFiles.files > ListLength > Template "{n} fichiers a traiter".

ListGetoperator.list_get

L'element a un rang donne (0 = premier, -1 = dernier). Si le rang n'existe pas : found faux et default.

  • Entrees : list, index. Sorties : item, found.
  • Reglage : default.

Exemple : ListSort (date) > ListGet -1 pour le fichier le plus recent.

ListFilteroperator.list_filter

Garde les elements qui passent un motif facon Houdini, sur le nom ou sur le chemin entier ; les autres sortent par rejected.

  • Entree : list. Sorties : items, rejected.
  • Reglages : pattern, match_on (name ou path).

Exemple : ListFilter (*.exr ^*_denoise*) pour garder les images de rendu sans les passes debruitees.

ListSortoperator.list_sort

Trie une liste : par nom, par date ou taille (fichiers), ou en ordre naturel (v2 avant v10).

  • Entree : list. Sortie : items.
  • Reglages : key (name, date, size, natural), reverse.

Exemple : ListSort (natural, reverse) > ListGet 0 pour la version la plus haute.

ListUniqueoperator.list_unique

Retire les doublons en gardant l'ordre de premiere apparition.

  • Entree : list. Sortie : items.

Exemple : liste des artistes ayant publie aujourd'hui, sans repetition, avant de les pinguer.

ListAppendoperator.list_append

Renvoie une nouvelle liste avec l'element ajoute a la fin (la liste d'origine ne change pas).

  • Entrees : list, item. Sortie : items.

Exemple : ajouter le dossier LAST a la liste des dossiers a zipper.

PathJoinoperator.path_join

Joint un dossier de depart et jusqu'a 3 morceaux relatifs.

  • Entrees : base, a, b, c. Sortie : path.

Exemple : PathJoin (FlowInput dest_folder, DateNow.date) > MakeDir : un dossier par jour.

PathSplitoperator.path_split

Decoupe un chemin : dossier parent, nom complet, nom sans extension, extension.

  • Entree : path. Sorties : parent, name, stem, ext.

Exemple : PathSplit.stem > Template "{stem}_proxy.usd" pour nommer un fichier a cote de sa source.

PathRelativeoperator.path_relative

Chemin relatif a un dossier de reference.

  • Entrees : path, base. Sortie : relative.

Exemple : ecrire dans un rapport les chemins relatifs au projet plutot que des chemins absolus de poste.

PathFluxTokenoperator.path_flux_token

Passe d'un chemin absolu a la forme portable $FLUX/..., et inversement. La forme $FLUX marche sur tous les postes.

  • Entree : value. Sorties : token (forme $FLUX/...), path (chemin absolu).

Exemple : PathFluxToken.token > WriteJson pour stocker un chemin lisible depuis n'importe quel poste.

DateNowoperator.date_now

Date et heure au moment ou le node est lu : en ISO, en date AAAA-MM-JJ et en secondes.

  • Sorties : iso, date, epoch.

Exemple : DateNow.date > PathJoin pour un dossier de dailies date du jour.

DateFormatoperator.date_format

Met une date ISO en forme avec un format strftime (%Y%m%d, %d/%m %H:%M...).

  • Entree : iso. Sortie : text.
  • Reglage : fmt.

Exemple : DateNow.iso > DateFormat (%Y%m%d) > nom de zip livraison_20261023.zip.

DateAddoperator.date_add

Ajoute (ou retire, en negatif) des jours et des heures a une date.

  • Entree : iso. Sortie : iso.
  • Reglages : days, hours.

Exemple : DateAdd (days: -7) > FindPublishes date pour lister les publishs de la semaine passee.

Actions

Agir sur les fichiers et le poste. Nodes a effet : simules pendant un essai a blanc.

Runaction.run
