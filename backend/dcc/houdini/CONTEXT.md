# CONTEXT - `backend/dcc/houdini/`

> Reecrit court le 2026-09-16 (V7-05). Ancienne fiche detaillee de mai 2026 retiree (lisible au tag `archive/pre-cleanup`).

`flux_houdini_server.py` (HTTP in-app 48884..48891, refuse les navigateurs S2), `client.py`, `shot_sync.py` (stages de shot regeneres par Production pousses aux Houdini ouverts : `refresh_from_flux` des FLUX Shot), `houdini_export.py` / `houdini_import.py` / `houdini_usd_light_export.py`, `autostart.py` (package `packages/flux.json` + favoris `jump.pref` `$FLUX/` et `$FLUX/DOSSIER_PROJETS/` ajoutes a l'installation, retires a la desinstallation), `hda/` (HDA importer/exporter/lighting ; `hda/flux_work_hda.py` = HDA FLUX Work SOP / LOP, une scene `.hip` par travail, ADR 0090 ; `work_open.py` = ouverture d'un travail depuis Production via `/run` ou lancement ; `work_template_build.py` = templates `.hip` (hython)), `startup/`.

Ne jamais ecrire dans `houdini.env` (crash Houdini 22). Ne jamais exposer le `usd-core` pip au Python de Houdini.

Import USD "Ouvrir dans Houdini" (2026-09-17) : toujours par contexte (`create_usd_context_import`, sonde pxr `features/importer/usd_probe.py`) : `/stage` = Reference LOP (`/assets/<X>` component ou skeleton, `/sets/<X>` assembly), `/obj` ou SOP = HDA `flux_importer` dont la Source vise le meme fichier (`library_import.importer_source_for_file` : tokens si le publish se resout sur ce fichier, Bibliotheque pour un component / assembly LAST ou vNNN, sinon chemin libre) ; sans HDA : `kinefx::usdcharacterimport` si skeleton, sinon `usdimport`. Tokens : un USD en couches `<base>_vNNN/<base>.usd` est liste et resolu par iteration. Export SOP `.usd*` = `usdexport` (plage = un fichier anime), jamais `rop_geometry`.

Import LOP Reference / Payload / Sublayer (2026-09-24) : `import_into_lop` + `POST /dcc/houdini/import/lop` (menu "Houdini LOP : Reference / Payload / Sublayer" du Folder Manager). Tout format lisible par le USD de Houdini 22 (`LOP_FILE_EXTS` : usd*, abc, bgeo(.sc), geo, obj, fbx, vdb, gltf/glb, ply, stl), charge tel quel par les plugins de format, sans SOP. Node selectionne du meme genre (Reference LOP pour reference et payload, Sublayer LOP) : fichier ajoute en nouvelle entree (ou dans la derniere vide) ; sinon nouveau LOP branche apres la selection (sinon le display), hors reseau LOP -> `/stage`. Payload = Reference LOP `reftypeN = payload`. Prim : `reference_prim_path` pour un USD, `/<nom du fichier>` sinon. "Ouvrir dans Houdini" (mode auto) en contexte LOP : ajoute au Reference / Sublayer selectionne, reference un non-USD (plus de repli dans /obj), un USD sans cette selection garde le flux `flux_importer`. Code valide en hython 22.
Launcher : `PYTHONUSERBASE` retire de l'env (sinon Houdini charge le pxr pip du Python Store).
HDA `flux_importer` (2026-09-17) : parm `source_mode` = Publish (tokens) / Bibliotheque USD (`/dcc/houdini/importer/library`, `library_resolve`) / Chemin libre (`probe?file=`). Bibliotheque (2026-09-19) : `lib_kind` (asset / decor / shot) -> `lib_class` (assets) ou `lib_seq` (shots) -> `lib_item` filtre ; les items du backend portent `kind`, `class`, `seq`, `name` ; `on_lib_filter` garde l'element s'il passe le filtre, `_sync_lib_filters` (au resolve) recale les menus sur `lib_item`. Un USD avec skeleton passe `usd_character` a 1 : sortie 1 = mesh boneCapture (`kinefx::usdcharacterimport`), sorties 2-3 = skeleton repos / anime. Le module Python est servi par le backend (relancer FLUX), le `.hda` (parms, noeuds internes) est rebuild dans `resources/shelves/houdini/` puis recopie par `reconcile_installed_dccs` au demarrage.

Layout d'assembly (2026-09-17) : `houdini_layout.collect_layout(name)` lit les matrices locales des instances `<ASM>/<CLASS>/<INSTANCE>` sur le stage du node LOP selectionne (sinon display node) et les renvoie au backend (`features/usd_assembler/layout_publish.py` ecrit le layer). Rien n'est ecrit par Houdini.

Icone des HDA FLUX (2026-09-19) : section `IconSVG` = `resources/shelves/houdini/flux_hda.svg`, `setIcon("opdef:.?IconSVG")`. Pas de PNG en `IconImage` : Houdini 22 ne le dessine pas.

Contenu du component dans FLUX Import /stage (ADR 0023, 2026-09-24) : Source Bibliotheque + Asset -> dossier "Contenu du component" : multiparms GEO / GROOM / LOOKDEV / ANIM (preview) / AUTRES, une case par fichier (`<prefix>_on#`, id cache `<prefix>_id#`, `<prefix>_ok#` = 0 grise la case). Les cases vivent sur le node (`comp_memory` par component) ; `on_component_toggle` appelle `POST /usd/component/check` (grises + avertissements, jamais de deselection) et ecrit `comp_state` ; le LOP interne `apply_component` (Python Script) pose les selections de variantes sur `prim_path` et un warning de node. Proxies actifs par defaut, anims eteintes ; depuis 2026-09-26 tous les proxies (quel que soit leur type) sont dans la section `proxy_files` "GEOMETRIE PROXY" en haut (libelle "proxy de <fichier>"), repli sur la section du type si le HDA n'a pas encore ete rebuild. Un lookdev laisse sur toutes les geos ne tient que la geo de son nom (`component_recipe.claims`). Le SOP `/obj` n'a pas ce dossier. ADR 0024 : un link a variante pilote le variantSet de son block (case cochee = variante selectionnee, `[block = variante]` dans le libelle) ; un link en sublayer est affiche "toujours actif" (pas de set). ADR 0035 (2026-09-26) : un look publie avec des variantes d'assign ajoute une ligne par variante dans LOOKDEV (id `<look>@assign:<variante>`, variantSet `assign`, une seule cochee, la derniere gagne, rendues par `/usd/component/check`) : pas de rebuild. Export look Solaris : un `flattenstage` par variante d'assign (LOP Python temporaire qui pose la selection), un seul sans variant block.

FLUX Shot pour une scene a plusieurs shots (ADR 0023, briques du template du mainteneur) : `_branch_end` suit la branche du shot (s'arrete avant un merge ou un ROP) pour le light rig du shot et le rendu ; boutons "Creer le ROP du shot" (`/out/RENDER_<SEQ>_<SHOT>`, Karma, plage / camera / `render_picture` du node), "Rendre ce shot", "Rendre la sequence" (tous les FLUX Shot de la sequence, un echec n'arrete pas les autres). Plus de scene de sequence generee par FLUX (`houdini_sequence_scene.py` supprime).

2026-09-27 (ADR 0037) : FLUX Shot s'affiche "FLUX Shot Import" (type `flux_shot` inchange) ; ses boutons de rendu sont sur **FLUX Render** (`hda/flux_render_hda.py`, sous RENDER_SETTINGS : retrouve le FLUX Shot Import en amont, switch = entree active, "Creer le ROP du shot" / "Rendre ce shot" / "Rendre la sequence") ; `render_picture` / `render_rop` restent caches sur FLUX Shot pour les vieilles scenes. Section "Assets et variantes" : lignes `[prim, variant set]` dans `var_rows_json`, choix `var_selN`, appliques par le Python LOP interne `apply_variants` (code autonome, sans FLUX). **FLUX Sequence** (`hda/flux_sequence_hda.py`) : nombre de blocs de shots de la scene de rendu, clone le dernier bloc, ne supprime jamais ; le meme module sert au generateur hython.
Scene de rendu de sequence (ADR 0036, 2026-09-26) : `features/folder_manager/houdini_render_scene.py` pose un FLUX Shot par shot avec `light_node` = `SHOT_LIGHTS_<SH>` (le publish du light rig s'arrete aux lumieres) et un ROP deja relie ; "Creer le ROP du shot" rend `_branch_end` (lumieres + reglages Karma), plus `light_node`.
Evenements des HDA (2026-09-26) : OnCreated / OnLoaded marques Python par `setExtraFileOption("<section>/IsPython", True)` (+ `IsScript`) et appeles par `kwargs['type'].hdaModule()` (`hda_common.FINALIZE`, `flux_importer_hda`). Avant, ils tournaient en HScript et `hou.phm()` etait faux pendant le chargement : aucun node FLUX ne se resolvait a l'ouverture.

avec `run` / `state`) ; sans lui le singleton `houdini_client` (instance choisie dans FLUX), appels internes inchanges

(`backend/flux_flows/bridges/headless.py`). Nodes `hou*` : `backend/flux_flows/nodes/dcc_houdini.py`.
